## 3. 개발 작업 규칙

1. **현재 `main` 코드와 개발 기본 문서 3개를 먼저 확인**한다. 구현 여부는 코드가 최우선 근거다. 문서와 코드가 충돌하면 확인 후 문서를 정정하며, 문서에 맞춘다는 이유만으로 코드를 임의 수정하지 않는다.
2. 새로운 기능의 확정/예정/미확정을 분리한다. 과거 대화의 아이디어를 확인 없이 확정된 기능으로 승격하지 않는다.
3. 기능 수정은 `main`에서 분기한 별도 브랜치에서 수행하고 PR을 만든다. **`main` 직접 푸시 금지**. 작은 변경 단위, 최소 영향 범위, 회귀 테스트 우선.
4. `npm test` 및 `npm run build` 성공을 확인한 뒤 PR을 병합한다. 실패 시 원인을 해결하고 다시 검증한다. 통과하지 않은 작업을 완료로 보고하지 않는다.
5. 사용자가 변경을 **사전 검토**하도록 요청했다면 분석/보고만 하고 승인 전 수정하지 않는다. 명시적으로 진행을 승인하면 개발할 수 있다.
6. 전투 공식·보상·진행 규칙·세이브 호환성·UI 레이아웃에 대한 임의 변경을 피한다. 리팩터링은 기존 동작을 유지하는 것이 기본이다.
7. 검증 결과를 보고할 때는 **코드 변경 / 테스트 / 빌드 / PR / 병합 / 배포 / 실제 브라우저 검증**을 각각 구분한다. CI 통과가 브라우저 실사용 검증을 의미하지는 않는다.
8. 원작 분석 시 저장소에 있는 배포용 압축 코드는 원본 개발 소스와 다를 수 있다. 확인한 사실과 추정한 설계를 구분한다.

## 4. 문서 운영 규칙

- 기본 개발 문서 3개와 **가상 플레이 전용 문서 1개**를 유지한다. 별도 필요가 없으면 더 세분화하지 않는다.
- `개발 문서 읽어`: 본 문서 → IMPLEMENTED_SYSTEMS → PLANNED_SYSTEMS → VIRTUAL_PLAY_RULES 순으로 읽고 `main`의 현재 상태와 대조한다.
- `개발 문서 최신화`: 기본 문서 3개와 가상 플레이 규칙 문서를 읽고 최신 코드/새로 확정된 기획과 비교한 다음 **변경이 필요한 문서만** 브랜치+PR로 갱신한다.
- 기능 구현 완료 시 IMPLEMENTED_SYSTEMS를 갱신하고, 계획했던 기능이라면 PLANNED_SYSTEMS에도 완료/이관 상태를 남기거나 삭제 사유를 기록한다.
- 파일 내 **코드 대조 기준 커밋·검증일** 갱신. 단순 문서 변경으로 게임 시스템이 구현됐다고 서술하지 않는다.
- 문서 수준: 공식, 기본값, 보상, 해금 조건, 관련 파일, 알려진 미연결 사항을 명시. 코드가 아닌 대화 정보는 별도 출처/확정 상태를 표시한다.

## 8. 다음 대화 인수인계 — 2026-10-28 최신 작업 상태

### 확정 규칙: 변경 금지

1. **원작형 희귀도 추첨**: 행성 이동(`MOVE_PLANET`) 시 각 **슬롯을 독립적으로** 출현 판정. 확률 성공 뒤 후보 포켓몬 N종 중 정확히 **1종**을 선택. 1지역 6번 스타터 슬롯(`W010602`)은 이상해씨·파이리·꼬부기 중 **하나만 등장**하며, 장차 N종 선택 슬롯 추가 예정. 추첨 결과는 행성 이동 전까지 고정. 지역 탭 변경/세이브 복원/전투로 재추첨하지 않는다.
2. **희귀도 확률 감소 순서**: **동일 희귀도 → 전체 지역 번호 순(1~20) → 해당 지역 내 슬롯 순**. 지역 이동 때 감쇠 기준을 초기화하지 않는다. N종 선택형 슬롯은 후보 수와 무관하게 슬롯 **1개**다. 마지막 **영구 처치** 기준 슬롯과의 위치를 기반으로 원작 감소 계수 적용: 안흔한 1.1, 희귀 1.15, 전설 1.05, 신적 2.0. `raritySystem.js` 구현 기준과 비교하고, 임의로 지역별 분리 금지.
3. **희귀도 최대 확률 장기 목표**: 안흔한 60%, 희귀 30%, 전설 15%, 신적 7.5%, 초월적은 특수 조건. **현재 강화치와 구분**. `SU013`은 **40레벨, 레벨당 +1%p, 기존 가격 유지**. 안흔한 확률 ×1.5 강화는 **나중에 추가**, 이번 개발에서 미구현. 다른 희귀도 강화나 가격도 임의로 추가하지 않는다.
4. **포켓몬·지역 기획**: 20지역 계획. 지역별 일반 편성 목표는 **흔한 10 / 안흔한 8 / 희귀 6 = 24 슬롯**; 진화형·전설·신적 등급은 별도 추가. 3~20지역 구체 종 배치와 숫자·보상은 별도 승인 필요. 지역 해금은 현재 1지역 일반 포켓몬 **7종 첫 처치**로 베리숲 해금(스타터 출현에 따라 8종으로 변동시키지 않음).
5. **밸런스 보전**: 포켓몬 능력치·보상, 진화, 전투 엔진, 경제 생산식, 강화 가격 및 효과, 10회 처치 한도를 무단 수정하지 않는다. 가상 플레이는 `VIRTUAL_PLAY_RULES.md` 기준, 명시 요청 시 시행한다.

- **미정:** 차원이동 보너스, 테라파고스 조우/능력치, 테라피스 획득·승계, 메타몽 공격 타입 선택, 이후 보스와 차원, 저장·UI 세부 정책. 승인 없이 임의로 확정/구현하지 않는다.

### 2026-10-29: 첫 행성이동 안흔한 해금과 고라파덕 안내
- 첫 번째 행성은 안흔한 자연 등장 확률 0%. **첫 행성이동 완료 후** 모든 후속 행성의 안흔한 기본 확률을 영구적으로 **5%** 적용한다.
- 노말 영구 강화 **SU013**은 레벨당 안흔한 확률 **+1%p**, 최대 **35레벨**로 조정한다. 기본 5% + 35레벨 = **40%** (향후 계획된 ×1.5 강화 적용 시 60%; ×1.5 강화는 현재 미구현).
- **두 번째 행성에서만 고라파덕(W010302)을 확정 등장**시킨다. 다른 안흔한 포켓몬은 기존 슬롯별 독립 추첨이며 세 번째 행성부터 고라파덕도 확률 추첨으로 복귀한다.
- 행성이동 시 전체 등장 슬롯 일괄 추첨·확정, 해금 순서, 지역 조건, 기존 슬롯별 확률 감소 기준은 변경하지 않는다. 기존 세이브의 이미 추첨된 슬롯 결과는 재추첨하지 않는다.
