# PokeLoop 구현 예정 및 미확정 시스템

> 최초 정리: 2026-10-26 | 코드 대조 기준 `d32cd151fe38876064dc7e7b82c07a21e3ced992`
> 실제 동작하는 기능은 [IMPLEMENTED_SYSTEMS.md](./IMPLEMENTED_SYSTEMS.md), 작업 규칙은 [DEVELOPMENT_GUIDE.md](./DEVELOPMENT_GUIDE.md).

## 1. 시스템별 개발 계획

| 항목 | 현재 상태 | 다음 단계 / 확인 사항 |
|---|---|---|
| **타입 동화도** | **설계 중 / 전투 미연결** | 과거 논의에서 기존 포켓몬 타입 상성에 타입별 동화도를 추가하고 자속 효과도 동화도에 반영하기로 함. 타입별 동화도 획득 수단은 미확정. 현재 `DittoPage.jsx` 동화도 탭은 안내 문구이며 `resolveAttack`에는 타입 배율 계산이 없음. 정확한 최종 배율표·저장 방식·획득 및 표시 정책 확인 후 구현. |
| **포켓몬 타입 상성/자속(STAB)** | **설계 중 / 전투 미연결** | 포켓몬 타입 데이터는 존재하나 실제 공격 계산에 상성·자속 적용 경로 없음. 기존 합의의 타입 상성+동화도 관계를 재검토 후 구현. 포켓몬의 4개 기술 시스템도 현재 공격 엔진의 단일 동작 모델과 구분해야 함. |
| **고정 데미지** | **보류** | `is-fixed` 흰색 팝업 CSS는 있으나 실제 고정 피해 채널은 아직 없음. 고정 피해를 발생시키는 기술/규칙이 확정되면 계산과 이벤트를 연결. 독 피해를 고정 피해로 오인하지 말 것. |
| **보너스 탭/보너스 효과** | **설계 중** | 탭은 존재하지만 효과 로직 없음. 획득·중첩·적용 시점과 UI를 기획 후 구현. |
| **도감 확장** | **설계 중** | 도감 화면은 준비 중 안내 단계. 내부의 `dexDiscovered` 기록을 활용해 도감 UI·보상/목표 등을 확정해야 함. |
| **안흔함 포켓몬 등장/희귀 확률** | **설계 중 / 일부 기반 구현** | 이상해씨·파이리·꼬부기 후보, 피카츄 등장 플래그, 희귀 확률/진화 판정 필드는 있으나 기본 스타터 발생 확률 0이며 재등장/재시도 정책 불명확. 실제 출현 트리거와 빈도를 먼저 확정. |
| **추가 진화 시스템 확장** | **일부 구현 / 확장 설계 중** | 현재 캐터피→단데기, 뿔충이→딱충이의 1회 첫 승리 판정은 작동. 다른 종, 다단계 진화, 희귀 진화와 사이클 변경 시 재판정할지 등은 별도 승인 필요. |
| **게임 장기 목표/완결 구조** | **설계 중** | 다층 내부세계 및 행성 이동은 존재하나 최종 목표·엔딩·추가 지역 확장 정책은 문서상 확정되지 않음. 원작 엔딩을 무조건 복제하지 말 것. |
| **향후 지역·포켓몬 추가** | **아이디어 / 미확정** | 야생 지역은 현재 시작의 평원과 베리숲. 새 지역의 적 순서·능력치·처치 보상·해금 조건·등장 규칙은 개별 확정 후 `wildData.js`에 추가. |
| **영구 업그레이드 활용 확장** | **설계 중** | `permanentUpgrades` 보관/승계 구조는 있지만 구매 목록, 성장 규칙, 스텔라 소비 설계는 아직 별도로 확정되지 않음. |
| **CSS 추가 중복 정리** | **기술 부채** | 일부 중복만 제거됨. `src/styles/40-world-overrides.css`를 포함해 CSS cascade와 반응형 레이아웃을 확인하며 점진적 정리. 모바일 시각 회귀 확인 필요. |
| **실사용 장시간/모바일 검증** | **검증 필요** | 브라우저에서 전투, 탭 전환, 저장, 자동화, 오프라인 복귀, 행성 이동을 실제 재현해 CI 밖 오류를 확인. |

## 2. 이미 구현된 사항 — 다시 개발하지 말 것

- 물리 빨강/특수 파랑/독 보라 데미지 팝업 및 종료 후 표시 유지; 고정 피해 **색상만** 준비됨.
- 첫 세 마리 해금과 서로 다른 종 첫 처치에 따른 추가 해금.
- 베리숲, 일반 진화 자식의 첫 승리 판정 및 등장, 처치 10회 상한, 감소 보상.
- 마비·독·해독, 두 자동화(끝없는 허기/불굴의 의지), 6개 강화.
- 내부세계 10계층, 타입 에너지→입자 구매, 스텔라 생성과 행성 이동, 저장 v10/오프라인 생산.
- 리팩터링: 구형 UI 제거, 능력치 표시 메타데이터 공통화, 전투 시각 이벤트 분리, 테스트 위치 통합. **코드를 읽고 변경 필요성을 확인한 뒤 진행**.

## 3. 논의/확정사항 관리

1. 게임 규칙이 확정되면 **결정일, 확정 값/공식, 변경 범위, 관련 코드, 남은 미정 항목**을 이 문서에 남긴다.
2. 단순 제안·추정·기술 아이디어는 확정으로 표기하지 않는다.
3. 기능이 코드에 병합되면 구현 문서에 옮기고 이 문서의 상태를 완료 처리하거나 목록에서 제거한다.
4. 문서만 변경됐을 때 게임 기능이 구현됐다고 주장하지 않는다.
5. 과거 합의에 등장하더라도 코드 근거가 없으면 검증 상태를 적고, 특히 **동화도 상세 공식 / 기술 4개 / 진화 재판정 / 엔딩**은 구현 전 재확인이 필요하다.
