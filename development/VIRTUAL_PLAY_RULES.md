# PokeLoop 가상 플레이·행성 이동 검증 규칙

> 분리/확장: 2026-10-27 | 원본: [DEVELOPMENT_GUIDE.md](./DEVELOPMENT_GUIDE.md)의 기존 §5
> **가상 테스트 실행 정책** 문서이며 게임 내 행성 이동 조건이나 전투 밸런스를 변경하지 않는다. 실제 구현 사실은 [IMPLEMENTED_SYSTEMS.md](./IMPLEMENTED_SYSTEMS.md), 계획은 [PLANNED_SYSTEMS.md](./PLANNED_SYSTEMS.md)를 확인한다.

## 1. 야생 지역 가상 플레이 기본 규칙 (기존 확정: 2026-10-26)

**사용자가 명시적으로 가상 플레이를 요청한 경우에만** 실제 게임 상태 전이(`transition`)와 전투 엔진으로 가상 시뮬레이션을 진행한다. 일반적인 패치에는 가상 플레이 분석을 자동 포함하지 않는다. 적 스탯·포켓몬 해금·재화·HP·독 상태를 임의 조작해 유리한 결과를 만들지 않는다.

1. **자동화:** 획득한 타입 에너지로 구매 가능한 자동화는 가능한 대로 구매한다. 특히 **끝없는 허기**를 구매·활성화하여 승리 후 **남은 HP와 상태이상이 이월되는 실제 연속 전투**를 수행한다. 자동화의 해금 조건과 비용, 재시도·회복 시간을 준수한다.
2. **기본 순회:** 각 포켓몬은 우선 **5회 처치**를 목표로 하고, 목표 달성 시 다음으로 진행한다. 다섯 번째 승리에서 자동 반복이 더 진행되지 않도록 토글을 관리한다. 포켓몬당 실제 게임 처치 상한은 10회.
3. **2차 전체 최대 처치 순회:** 실제 등장한 모든 적의 누적 5회 목표를 완수하고 보류 목록을 모두 해결한 다음, 각 지역의 실제 등장 순서(진화체는 부모 바로 다음)를 다시 순회해 모든 적을 상한 10회까지 추가 처치한다. 이미 10회면 건너뛴다. 2차 순회 중 패배하면 앞선 도전 가능한 적을 최대치까지 파밍하고 다시 도전하며, 계속 실패하면 보류 후 다른 적을 진행하고 복귀한다. 5회 및 10회 완료를 구분하여 기록한다.
4. **연속 전투 측정:** 대상마다 한 번의 전투 시작에서 자동 반복으로 이어진 **최대 연속 승리 횟수**와 전투 시도별 연속 승리·패배, 현재 누적 처치 수를 기록한다. 도전 성공 전 HP·독이 초기화되는 별도의 전투 시도들을 합산해 하나의 연속 기록으로 보고하지 않는다.
5. **패배 시 파밍:** 먼저 처치했던 접근 가능한 포켓몬들을 최대 **10회 누적 처치**까지 추가로 잡아 성장하고, 패배했던 포켓몬에 재도전한다. 파밍 과정의 처치와 연속 승리도 기록한다.
6. **재도전 실패:** 추가 파밍 후에도 패배하면 대상은 보류하고 **도전 가능한 다음 포켓몬을 5회 처치**한 뒤 보류한 대상으로 돌아와 다시 시도한다. 진화체나 확률 등장 등 실제로 나타나지 않거나 잠긴 포켓몬은 임의 활성화하지 않는다.
7. **구매 정책:** **끝없는 허기·불굴의 의지 두 자동화 모두** 재화가 충족되는 즉시 구매하고, 연속 전투 기록을 위한 끝없는 허기를 기본 활성화한다. 불굴의 의지의 자동 재도전은 일반적인 전투 실패 후 파밍·보류 우선순위를 깨뜨리지 않도록 토글을 관리한다. 강화는 **현재 구현된 강화 16종 전체(목록은 `src/core/shopSystem.js`의 `UPGRADES`가 기준)**를 대상으로, **구매 가능한 항목 중 강화 레벨이 낮은 순서**로 시도해 고르게 구매한다. 필요한 타입 에너지가 부족하면 해당 항목을 건너뛰되 재화 확보 시 다시 시도하며, 실제 획득 재화만 사용한다.
8. **지역 해금:** 실제 등장한 **비진화 포켓몬 전체(확률 등장 포함)의 70% 이상 서로 다른 종 첫 처치**로만 다음 지역을 해금한다. 진화체는 분모와 분자에서 제외한다.
9. **순서형 타임라인(필수):** 보고서에는 **경과 시간/시각을 넣지 않고**, 전 종 누적 5회 목표 달성까지 발생 순서대로 자동화 구매·강화·적 도전·연속 처치·실패·이전 적 10회 파밍·재도전·보류·복귀·지역 해금 과정을 상세히 기록한다. 이후 10회 완료 단계는 간략한 요약만 작성한다. 연속 승리 횟수는 개별 전투 시작 단위로 명시하고 5회 목표 중단과 구별한다. 시간 측정값이 필요하면 별도 선택 지표로만 제공한다.
10. **결과 보고:** 지역/포켓몬별 첫 승리, 목표 5회 달성, 최대 연속 승리, 추가 파밍 횟수, 패배 횟수, 보류·재도전·미해결 목록, 자동화/강화 구매, 지역 해금 및 5회 완료까지의 순서형 타임라인을 기록한다. 전 종 최대 10회 완료 후 최종 메타몽 실효 능력치·최종 강화·타입별 누적 획득 에너지·실제 남은 에너지·구매 사용량도 보고한다. RNG 방식(고정 난수/시드), 시뮬레이션 제한과 테스트 불확실성을 밝힌다. 5회까지 달성하지 못한 포켓몬을 성공으로 표기하지 않는다.
11. **회귀 검증:** 게임 로직 변경 시 `npm test` 및 `npm run build`를 통과시키고, 과거 지역 편성처럼 오래된 수치에 종속된 테스트와 **실제 진행 불가 버그**를 구별하여 수정한다. 검증 기준을 낮추어 통과 처리해서는 안 된다.

### 기존 가상 검증의 구현 범위

- 검증용 실행 파일은 `tests/hungerFiveStreaks.test.js`이다. 실제 `transition` 및 `COMBAT_TICK`을 사용하고 난수값 `0.5`를 고정하여 재현한다. `balanced`, `attack`, `hp`, `none` 전략을 테스트하며 기본 분석 리포트는 `balanced` 경로다.
- **현행 기본 상태에서는 1지역 스타터와 베리숲 피카츄가 나타나지 않는다.** 따라서 해당 고정 등장 설정에서 기본 5회→10회 완주 대상으로 간주하는 포켓몬은 1지역 10종 + 2지역 일반 10종 및 진화체 2종 = **22종**이다. 확률 등장 종이 추가되면 실제 등장 명단을 기준으로 검사한다.
- 실제 게임 플레이와 같은 **모든 난수 분포의 승률 검증이나 브라우저 자동 플레이를 뜻하지 않는다.** 시뮬레이션 정책상 `불굴의 의지` 자동 재도전은 구매하되 비활성화해 수동 파밍/보류 순서를 지킨다.
- 단일 행성 보고 시 5회 달성까지 **상세 타임라인**, 이후 10회까지 **간략 요약**, 완료 시 **최종 실효 능력치·강화 레벨·타입별 누적 에너지/지출/잔액**을 분리한다. 니드런♂·♀의 첫 처치 직전 능력치/강화 정보는 테스트 리포트에 기록된다.


## 2. 행성 이동을 포함한 다회차 가상 플레이 (추가 확정: 2026-10-27)

### 2.1 이동 원칙과 두 가지 사유

- **현재 행성에서 더 이상 처치 가능한 적이 없을 때 행성 이동**을 검토한다. 임의 SE 목표량이나 고정 시간으로 이동 시기를 강제하지 않는다.
- **완주 이동:** 해당 회차에 실제 등장하고 해금 가능한 모든 대상의 처치 상한(현재 각 10회)을 채웠으며, 열릴 수 있는 지역·대상이 더 없을 때 이동한다. 이미 5회만 채웠다면 10회 2차 순회를 먼저 진행한다.
- **성장 정체 이동:** 달성하지 못한 대상은 남았지만 §2.2의 검증을 모두 거쳐 더 진행할 수 없을 때 이동한다. '절대 처치 불가능'이 아니라 **지정된 재도전 정책하의 정체**로 기록한다.
- 미등장 희귀종, 확률 등장 실패 진화체, 아직 실제 해금되지 않은 적을 임의로 생성하거나 해금하지 않는다. 단, 접근 가능한 적의 첫 승리로 새로운 대상/지역을 해금할 수 있다면 이동하지 않고 진행한다.
- 이동은 실제 `transition(state,{type:'MOVE_PLANET'})`으로만 한다. 전투 중, 패배·도주 후 회복 중, 일시정지/종료 상태 등 실제 이동이 차단된 상황에서는 이동하지 않는다.

### 2.2 패배·정체 판정 절차 (이 순서 준수)

1. 기존 §1에 따라 이미 처치한 **접근 가능한 적의 잔여 처치 횟수(최대 10회)**를 먼저 파밍하고 구매 가능한 강화·자동화를 규칙대로 구매한 뒤 실패한 적에게 재도전한다.
2. 그래도 실패하면 그 적을 **보류**하고 다른 도전 가능한 적을 진행한다. 첫 승리/성장/지역 해금/강화 구매 등 전투 조건이 바뀌면 보류 대상을 다시 검사한다.
3. **동일한 성장·강화·상대 조건에서 최대 5번의 독립 전투 시도**를 허용한다. 5번 모두 패배하면 `재도전 제한 도달`로 보류한다. 1~4번 실패 중 승리하면 정상 진행한다. 한 번의 자동 연속 전투에서 나온 여러 승리를 여러 독립 시도로 합치지 않는다. 성장이나 구매로 조건이 달라지면 시도 횟수를 새로 센다.
4. 모든 접근 가능한 적의 잔여 파밍·다른 대상 진행·보류 대상 재도전을 마친 다음, **현재 보유 타입 에너지로 즉시 구매 가능한 강화 및 자동화가 없는지** 확인한다. 있다면 먼저 구매하고 영향받은 대상에 재도전한다.
5. 접근 가능한 적이 모두 상한에 도달했으면 **완주 이동**, 상한 미달 대상이 남아 있으면서도 1~4를 더 진행할 수 없으면 **성장 정체 이동**으로 판정한다. 미등장/잠김 대상은 이유를 별도로 기록한다.
6. 위 5회 재도전 제한은 가상 테스트의 탐색 예산이며, 확률상 승리 가능성이 0임을 입증하는 기준이 아니다. RNG 고정값이 결과를 결정하는 경우에도 이를 실제 승률로 보고하지 않는다.

### 2.3 이동 전 재화·생산 처리

- 전투/강화/자동화는 실제 획득한 에너지만 사용하며, 보유 재화·입자·SE·처치 수·HP·상태이상을 조작하지 않는다.
- 전투 진행이 멈춰도 입자 및 대기 SE 생산은 이어질 수 있다. **행성 이동을 위해 SE 1 또는 100 등 목표치를 맞출 때까지 무기한 대기하지 않는다.** 테스트가 실제로 실행한 경제 틱/오프라인 생산만 인정한다.
- 이동 직전 대기 SE(`pendingStellar`), 사용 가능 SE(`stellar`), 누적 획득 SE(`totalStellarEarned`)를 구분해 기록한다. 대기 SE 0 또는 1 미만이라도 현재 게임의 이동 조건을 충족하면 이동할 수 있으며, 이 경우 구매 가능한 영구 강화가 없을 수 있음을 명시한다.
- 생산만 더 기다릴 경우 다른 결과가 날 수 있으므로 **경제 생산만 기다리지 않은 테스트 정책의 한계**를 보고한다.

### 2.4 실제 이동·영구 강화·다음 회차

1. `MOVE_PLANET` 직전과 직후 상태를 기록하고, 흡수 SE 및 초기화/승계 필드를 코드 기준으로 비교한다.
2. 이동 뒤 현재 **구매 가능한 영구 강화(SU)**를 실제 `BUY_STELLAR_UPGRADE` 액션으로 구매한다. 현재 구현된 노드 기준 추천 구매 우선순위는 **SU012(공격 +1) → SU011(HP +10) → SU013(전투 노말에너지 +10%)**다. 비용·소유·해금 조건을 지키며, 향후 노드가 추가되면 구매 정책을 다시 확정한다. 이는 **테스트 전략**이지 게임의 자동 구매 기능이 아니다.
3. 메타몽 기본 능력치, 이번 회차 처치 수, 일반 강화/자동화/에너지/입자/생산 구매 등은 실제 이동 결과대로 초기화한다. 영구 SU, 도감 발견·누적 처치, 도구, 노말 첫 이정표 등은 코드가 승계한 것만 인정한다.
4. 다음 행성에서 기존 §1의 **5회 상세 → 10회 간략** 공략을 처음부터 반복한다. 확률 판정은 실제 코드 경로와 정해진 RNG 조건에 맡긴다.
5. 이전 행성과 **실제 누적 획득 SE, 구매 영구 강화, 첫 처치/5회/10회 성과, 패배, 시도/전투 횟수, 최종 실효 능력치**를 비교한다. 전투 진행 이외에 게임 내 소요 시간을 비교할 경우 경제 틱·회복 대기 시간을 같은 기준으로 측정한다.

### 2.5 무한 반복 방지 및 종료

- 이동 직후 다음 행성에 **구매 가능한 영구 강화가 없고**, 직전 회차와 비교해 **새로 확보한 SE, 신규 첫 승리, 특정 포켓몬 처치 도달 횟수 등 진전이 모두 없으면** 추가 이동을 멈추고 `진전 없음`으로 종료한다. 누적 SE가 실제로 증가 중이라면 이 조건만으로 즉시 종료하지 않는다.
- **안전 상한: 기본 10회 행성 이동.** 상한에 도달하면 현재까지의 결과를 보고하고 종료하며 자동으로 무한 회차를 진행하지 않는다. 이는 실제 게임의 제한이 아니라 테스트 실행 예산이다.
- **예외:** 아직 행성 이동/영구 강화 동작을 포함하지 않는 기존 테스트 스크립트만 실행한 경우, 단일 행성 결과를 다회차 검증으로 보고하지 않는다. 필요하면 별도 테스트 구현 후 실제 실행 결과를 제시한다.
- 진행 자체가 불가능하고 대기 SE 생산도 없거나 실제 테스트 자원 한도에 도달하면 원인과 미검증 구간을 밝히고 중단한다. 임의 보상/대기시간 건너뛰기로 결과를 만들어내지 않는다.

### 2.6 다회차 보고서 형식

- **행성별 5회 목표까지:** 기존 §1의 시간 없는 **상세 순서형 타임라인**(전투, 파밍, 패배, 자동화/강화, 보류·복귀·해금 포함).
- **각 행성 5→10회:** 간략한 결과 요약. 5회 미달 대상도 숨기지 않는다.
- **이동 직전:** 완료·미완료 포켓몬, 미등장/잠김 제외 대상, 정체/완주 사유, 마지막 실효 스탯, 16종 강화, 타입별 누적 획득·사용·잔여 에너지, 입자 상태, 대기/잔여/누적 SE, 자동화·생산 구매, 패배/재시도 횟수.
- **이동 직후:** 실제 획득 SE, 새로 구매한 SU와 소비 SE, 승계·초기화 상태 및 다음 회차 초기 능력치.
- **최종:** 행성 간 처치 성과·전투 시도·패배·성장·SE 생산/소비 비교, 완료/정체/안전 상한 중단 여부, RNG 정책과 재현성 및 브라우저 미검증 여부.
- 기존 §1의 **니드런♂·♀ 첫 처치 직전 스탯/강화** 측정과 지역별 상세 기록은 유지한다.

## 3. 구현 상태와 운영 주의

- 현재 저장소의 `tests/hungerFiveStreaks.test.js`는 **단일 행성** 가상 검증용이다. 이 문서의 행성 이동·SU 구매·다회차 종료 규칙을 충족하는 자동화 스크립트가 구현·실행되었다고 간주하지 않는다.
- 이 파일은 **시뮬레이터 테스트 정책**이며 실제 플레이 규칙·밸런스·행성 이동 버튼의 이용 가능 조건을 수정하라는 요구가 아니다.
- 기능 코드 변경 시 개발 가이드의 별도 브랜치 → PR → `npm test`·`npm run build` → 검증 후 병합 절차를 따른다. 문서만 바꾸었다면 테스트 실행 여부를 구분하여 보고한다.
